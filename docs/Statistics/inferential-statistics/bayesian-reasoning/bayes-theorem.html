Bayes' Statistics (Bayes' Theorem)

Bayesian statistics is an approach to data analysis and parameter estimation based on Bayes' theorem. Where the hypothesis tests so far ask "how surprising is this data if the null is true?", Bayes flips the question to the one you actually care about: "given the data, how probable is my hypothesis?" To get there we start from the two flavours of probability.

Independent vs dependent events​

① Independent events — one outcome tells you nothing about the next.

  • Rolling a die over {1,2,3,4,5,6}\{1, 2, 3, 4, 5, 6\}{1,2,3,4,5,6}: each face has P(1)=P(2)=⋯=16P(1) = P(2) = \dots = \tfrac{1}{6}P(1)=P(2)=⋯=61​, and the previous roll doesn't change the next.
  • Tossing a coin: P(H)=0.5, P(T)=0.5P(H) = 0.5,\ P(T) = 0.5P(H)=0.5, P(T)=0.5, every toss fresh.

② Dependent events — one outcome changes the probability of the next. Draw balls from a box without replacing them and the mix shifts as you go. Say the chance of drawing red is P(R)=25P(R) = \tfrac{2}{5}P(R)=52​, and then — with one ball already gone — the chance of yellow becomes P(Y∣R)=34P(Y \mid R) = \tfrac{3}{4}P(Y∣R)=43​. That second term is a conditional probability: the probability of YYY given that RRR already happened.

Conditional probability and the multiplication rule​

The probability of both dependent events is the first times the second-given-the-first:

P(R and Y)=P(R)⋅P(Y∣R)⏟conditional=25⋅34=620P(R \text{ and } Y) = P(R)\cdot \underbrace{P(Y \mid R)}_{\text{conditional}} = \frac{2}{5}\cdot\frac{3}{4} = \frac{6}{20}P(R and Y)=P(R)⋅conditionalP(Y∣R)​​=52​⋅43​=206​

Deriving Bayes' theorem​

Here's the one clever step. The probability of "AAA and BBB" can't depend on the order you name them:

P(A and B)=P(B and A)P(A \text{ and } B) = P(B \text{ and } A)P(A and B)=P(B and A)

Write each side with the multiplication rule:

P(A)⋅P(B∣A)=P(B)⋅P(A∣B)P(A)\cdot P(B \mid A) = P(B)\cdot P(A \mid B)P(A)⋅P(B∣A)=P(B)⋅P(A∣B)

Now just divide to isolate the conditional you want. Solving for P(B∣A)P(B \mid A)P(B∣A):

P(B∣A)=P(B)⋅P(A∣B)P(A)P(B \mid A) = \frac{P(B)\cdot P(A \mid B)}{P(A)}P(B∣A)=P(A)P(B)⋅P(A∣B)​

or, the form we'll use most, solving for P(A∣B)P(A \mid B)P(A∣B):

 P(A∣B)=P(A)⋅P(B∣A)P(B) ⇐ Bayes’ theorem\boxed{\,P(A \mid B) = \frac{P(A)\cdot P(B \mid A)}{P(B)}\,} \qquad\Leftarrow\ \textbf{Bayes' theorem}P(A∣B)=P(B)P(A)⋅P(B∣A)​​⇐ Bayes’ theorem

Reading each term, where A,BA, BA,B are events:

  • P(A∣B)P(A \mid B)P(A∣B) — probability of AAA given BBB is true (the posterior — what we want).
  • P(B∣A)P(B \mid A)P(B∣A) — probability of BBB given AAA is true (the likelihood).
  • P(A)P(A)P(A) — the standalone probability of AAA (the prior).
  • P(B)P(B)P(B) — the standalone probability of BBB (the evidence, a normalizer).

The base-rate trap — see it​

Bayes matters most when your intuition fails, and it fails hardest on rare events. A test can be "90% accurate" and yet a positive result still mean you're probably fine — because a small prior P(A)P(A)P(A) drags the posterior P(A∣B)P(A\mid B)P(A∣B) far below the test's accuracy. From theorem to classifier: Naive Bayes​

Bayes' theorem is also the engine of a real machine-learning model. Take a house-price dataset with independent features — size of house x1x_1x1​, number of rooms x2x_2x2​, location x3x_3x3​ — predicting a dependent output yyy (the price). Bayes gives the probability of an output given the features:

P(y∣x1,x2,x3)=P(y)⋅P(x1,x2,x3∣y)P(x1,x2,x3)P(y \mid x_1, x_2, x_3) = \frac{P(y)\cdot P(x_1, x_2, x_3 \mid y)}{P(x_1, x_2, x_3)}P(y∣x1​,x2​,x3​)=P(x1​,x2​,x3​)P(y)⋅P(x1​,x2​,x3​∣y)​

Assume the features are (naively) independent given yyy and this becomes the Naive Bayes classifier — cheap, surprisingly strong, and the classic baseline for spam filtering and text classification.

# Bayes' theorem: the base-rate trap in numbers.
# A disease affects 1% of people. A test is 90% sensitive with a 9% false-positive rate.
# You test positive — what's the chance you actually have it?
prior = 0.01          # P(A): base rate
sens  = 0.90          # P(B|A): true-positive rate
fpr   = 0.09          # P(B|¬A): false-positive rate

p_B = prior*sens + (1 - prior)*fpr          # P(B): total prob. of a positive test
posterior = prior*sens / p_B                 # P(A|B): Bayes' theorem

print(f"P(positive test)          = {p_B:.3f}")
print(f"P(disease | positive) = {posterior:.3f}")   # ≈ 0.092 — only ~9%, not 90%!

Why a quant cares​

Bayes is the native language of decision-making under uncertainty, which is the whole job:

  • Updating beliefs with evidence. Start with a prior on a parameter (a stock's true drift, a regime probability), see data, and compute a posterior. That's Bayesian estimation — and the Bayesian Inference page has a prior→posterior updater you can drag.
  • The base-rate trap is a risk trap. "This alert is 95% accurate" is meaningless without the base rate of the thing it detects. Rare-event detectors — fraud, default, blow-up — are swamped by false positives exactly as the disease test is; ignoring the prior is how teams drown in false alarms or trust a bad signal.
  • A credible interval says what people think a confidence interval says. The Bayesian posterior supports the direct statement "95% probability the parameter is in this range" — the honest version of the frequentist confidence interval, and the basis of the ROPE decision rule.
